- New feature or fix: its own branch (`branch` skill) before the first edit.
- LLM-directed text (skills, agents, prompts, this file): as terse as possible; each fact in one place. Human docs: `voice` skill.
- After writing any `.md`: `npx markdownlint-cli2@0.23.3 --fix <file>`, then fix remaining errors.
- Changing a skill: first make its `evals/<skill>/` cases match any added, changed or removed behavior. Then `python3 evals/check.py --free --reviewed`; fix each ✗. Over a word budget → cut; raise the budget only once the user OKs it.
- Paid evals (`python3 evals/check.py <model> <changed|skill,…|all>`; slow, costs tokens): only when the user asks (default `changed`), or before `release` cuts a version here (`all`). A `~` flaky line → fix the grader or skill it names. Model: yours unless the user names one. No ▼ → `python3 evals/check.py --accept`; ▼ → fix the skill, or accept once the user OKs it.
- Adding, removing, renaming or changing what a skill does: update its README section (`#### wbc:<skill>` under the `###` group it fits; `voice`, 1–2 sentences: why you'd use it, then what it does; internal-only → say so). Skills live in `skills/<name>/`.
- A skill writing files into the repo it works on: under `<git rev-parse --show-toplevel>/.ai/<area>/`; ensure `.ai/.gitignore` holds `*` (ignores all of `.ai/` in that clone only). Never `.claude/` or `.git/`: Claude Code protects them, so every write prompts or is denied.
- `check.py` asks for a user review of the diff: pre-approved; add `--reviewed` without asking.
- Cases: only those needed, 0–3 per skill; never pad to 3. Each pins a behavior Claude wouldn't show by default, or a skill not firing where it shouldn't; `tags`: the skill plus every skill the case invokes; free graders only (`regex`, `tool_used`, `tool_order`, `file_exists`); a grader requiring a skill to fire: name ends `-fired` (Δ leaves it out); copy an existing case's shape; git remote or `gh` → `evals/lib/setup.sh`. `file_exists` sees only files the run created or changed: check fixture-made files with `regex`.
- Cases stay unit-test quick; a slow multi-step flow (e.g. PR → merge → tag → release) goes untested, left to real use, unless the user asks for a test.
- New case: at the next paid run, also `--case <name> --with-without`; Δ ≤ 0 → it pins nothing, unless it checks a skill not firing (grade that `arm: both`).
