Splitting a branch: the request is its diff against the default branch, from where they diverge (`git diff origin/<default>...<branch>`); `status.md` gets `from: <branch>`. Never change, rebase or delete the branch. Step 4: specs for what the branch does. Step 6 reads the diff too; each task file's `from:` names the branch, and each task lists what it carries: whole files, else hunks by path and what they change. Every hunk goes to exactly one task, or step 7's reply names it left out. A version bump → its own task first, with tasks.md's upgrade ACs, redoing the manifest and lockfile change (their hunks: redone), then carrying the hunks that adapt code to it. A task changing no behaviour has one AC: `suite passes (no behaviour change: no new test)`.
